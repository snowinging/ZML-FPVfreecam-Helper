## 工具包

这里的脚本都围着同一件事转：把一台遥控器的通道摸清楚、写进 `~/.config/endfield-fpv/mapping.toml`，
再确认发出去的状态包是游戏端能认的。它们共用 `fpvhelper/` 那个包，因此必须在本仓库里运行
（脚本会自己把仓库根目录加进 `sys.path`，从哪个子目录调用都行，直接拷单个文件出去则会报找不到包）。

日常只需要 `ZML_FPVfreecam-HelperGUI.py`。其余几个在标定、排障时用，顺序大体是：

```
radio_probe --list        设备到底有几个接口、HID 名字是什么
fpv_monitor --list        程序自己能不能看到这台设备、有多少路通道
fpv_learn                 把通道号和功能名对上，写回 TOML
fpv_range                 摇杆推到死，确认记录的行程够宽
ZML_FPVfreecam-HelperGUI  日常改映射、看实时状态
fake_game                 不开游戏，先验一遍 UDP 链路
```

### ZML_FPVfreecam-HelperGUI.py

主界面。左侧通道位置条，右侧一行一个功能的映射编辑，底栏是发送开关与状态。tkinter 画的，
系统自带，无需额外安装。`--selftest` 不打开窗口，只验证输入设备是否可用（无图形环境或远程 ssh 时用）；
`--config` 指定另一份映射；`--send --port 47800` 启动后直接开始发送，不必手动勾选。

### fpv_learn.py

标定模式。先初查：把所有摇杆和开关都动一遍，程序列出哪些通道有变化、变化了多少；
再逐个功能标定，按提示把杆推到一端停住、回车，再推到另一端，程序据此得出通道号、行程、
中位与正反向，并写回 TOML。开关问两个位置，多档拨杆问多个位置。

`--dump` 只看当前映射不修改，`--funcs roll,pitch,yaw` 只标其中几项，`--no-discover` 跳过初查，
`--threshold` 调判定「这个通道动了」所需的最小行程比例（默认 0.15，通道噪声大时往上调）。
标定结果除更换遥控器外不用重复做。

### fpv_monitor.py

看设备当前上报什么。`--list` 列出可识别的输入设备；`--seconds N` 打实时柱状图；
`--dump` 只输出一次通道清单与原始值。映射没写好的时候，用它确认「是设备没读到」还是
「映射写错了」。`--backend hidraw` 可切到原始后端，`--match / --path` 手动指定设备。

### fpv_range.py

量程检查。采样一段时间，把各轴实际能到的范围与配置里记的 min/max 摆在一起比。
标定时若没把杆推到底，行程会被记得过窄，结果就是杆还没到头游戏里已经满杆，
整条曲线也被拉长，手感发飘。用法很简单：跑起来之后把每根回中杆推到四个角各停一下，
油门和旋钮走完全程，`--sec` 定采样时长（默认 25 秒）。

### radio_probe.py

HID 原始报文探针。不经过 evdev，直接读 `/dev/hidrawN`，列出候选遥控器、把原始报告打出来、
按字节统计活动范围，用来找 evdev 里看不见的通道（超过 8 路的、藏在厂商自定义报文里的开关）。

`--list` 列设备，`--bar` 实时打印 8 个通道的柱状图（标定时用），
`--seconds 120 --csv a.csv` 采 120 秒存成 CSV 慢慢看。设备节点的 udev 规则带 uaccess 标签，
普通用户有 ACL 权限，不用 root 也不用加规则。

### fake_game.py

假游戏端。绑在网口上收状态包，按协议解包、打出来，再回一个回执，因此不启动游戏也能验证
「打包对不对、有没有发出、延迟多大」。`--bars` 加条形图显示四路杆量，`--quiet` 只统计，
`--takeover` 在回执里报告「相机已接管」（用来检查模组侧接管状态是否正常显示），
`--seconds N` 跑 N 秒自动退出，`--port` 换端口（默认 47800）。
