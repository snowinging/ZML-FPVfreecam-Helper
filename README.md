
## 通道软映射（2026-10-11 定）

程序里不写死任何"第几路是油门"。设备只提供一串编号通道，通道叫什么、怎么归一化，
全在 `~/.config/endfield-fpv/mapping.toml`。换遥控器改配置，不改代码。

分层：
- `fpvhelper/channels.py` 输入层。后端 evdev / hidraw / serial(CRSF，预留)。
  evdev 是首选：内核已经把 HID 归一化成 ABS_X..ABS_THROTTLE + BTN_*，OpenTX/EdgeTX 的
  USB 摇杆模式都是这套，换遥控器基本只改 `[device] match`。hidraw 是备路，
  给 evdev 看不到的通道（超过 8 路、隐藏开关）用，布局用 offset/width/endian/count 描述。
- `fpvhelper/channels.py` 里的 `Mapping` 归一化。轴 -1..1、油门 0..1、开关 true/false、多档开关出档位序号，
  带 invert / deadband / expo / trim / rate。
- `fpvhelper/config.py` mapping.toml 读写（读 tomllib，写自己来）。

工具：
- `tools/fpv_monitor.py --list / --seconds N / --dump` 看设备里有几路、谁在动。
- `tools/fpv_learn.py` 学习模式：先侦查（把所有杆都过一遍，看哪几路动过），
  再逐功能学（"推到正方向到底 → 回车"、"推到反方向到底 → 回车"），
  自动得出通道号、min/max/中点、正反向，写回 TOML。开关问两个位置，多档问多个位置。

2026-10-11 这台 OpenTX BETAFPV LR3PRO（VID:PID 1209:4f54）在 evdev 下是 7 路
（ABS_X/Y/Z/RX/RY/RZ/THROTTLE，全是 0..2047）+ 24 个按键；/dev/input/event31 与 js0
带 logind 的 uaccess ACL，普通用户直接能读，hidraw14 同样。所以不用 root，也不用 udev 规则。
通道到物理杆位的对应关系**不猜**，等学习模式跑一遍再钉死。

## 配置台（GUI）

`tools/fpv_gui.py` 用 tkinter（系统自带，不用装东西）。
左边：每路通道的位置条（底色带 = 这次看到的活动范围，竖线 = 开界面时的静止位），
下面两个摇杆框，横纵各取映射里的一路，框的四条边写着这一路的正负：
右边/上边是正、左边/下边是负，勾了「反向」就自动对调，所以框里看到的就是程序最后输出的方向。
右边：一行一个功能，通道下拉 / 类型 / 反向 / expo / 死区 / 最小- / 中点 / 最大+ 三栏可手改。
最小那栏的字是冷色、最大那栏是暖色，行尾还有个实时的小符号：杆偏正方向显示 +，
偏反方向显示 -，回到中点附近就空着。行左侧的小色条：亮 = 当前选中，暗 = 还没标过。
换设备后如果映射的行程和当前设备对不上（比如插着 DJI C5 但配置还是 BETAFPV 的 0..2047），
连接时底栏会直接说要重标哪几路。

标定三种做法，都要点保存才落盘：
- 手动：直接改 最小/中点/最大。select 类型在中点栏填分界值，逗号隔开。
- 设中点：把杆放平，点一下，当前值就当中点。
- 校准（每行或底栏）：通道没绑时用这个。推到一头停住、再推到另一头停住，通道号、
  行程、正反向一起算出来。
- 自动行程 / 全部轴自动行程分两段。
  第一段是零位检测：开始之后就盯住参与的那几路轴，谁都别碰杆，连续 3 秒没动，
  就把当下这个位置记成中心（中途动一下会重新计时）。油门这类不能写中点。
  第二段才是行程：6 秒（单路）或 9 秒（全部轴）里把杆推到两头、多画几个圈，
  这段的 min/max 直接写进映射。开关不参与，开关用「校准」逐位认。

底栏另有 归中自检：只看弹簧回中的轴，偏超过量程 6% 就报是哪一路。
`--selftest` 不开窗口，只验证输入层能连上。
